## Context

The PHASE3C17 Install Lifecycle Verification (`docs/PHASE3C17_INSTALL_LIFECYCLE_VERIFY_REPORT.md`) proved that the extension install lifecycle is correct **only when** `AfterInstall.php` calls `DataManager::rebuild()`. Without that call, controllers, routes, entity registry, and ACL do not materialize on install — a regression to the R1.1 "404 Controller does not exist" failure mode.

However, commit `dca66c1` (`fix(phase3c16): remove runtime ddl and normalize workflow payloads`) inadvertently removed the `DataManager::rebuild()` call from `crm-extension/scripts/AfterInstall.php`. The canonical deployment ZIP (`deployment/prospecting-extension-1.9.10-alpha.zip`) was subsequently regenerated from that source, producing a stale artifact that lacks the rebuild call.

This reconciliation restores the verified AfterInstall contract and rebuilds the canonical artifact.
